# 私密互传与按需填入

2026-11-07：本文描述 0.4.2 的私密流程。用户已确认 v0.3.8 魅族到华为和台式机可用；其他方向、笔记本和各应用自动填写仍待验收。用户已取消冻结并恢复开发，不把局部确认扩展为所有机型通过。原始反馈见[问题分析](../notes/private-transfer-037-review.md)。

## 已确定的使用流程

**在 1Password 正常复制 → 敏感标记触发自动私密发送 → 已直接配对且开启接收的在线设备临时接收 → 需要时直接填入。**

无需每次打开猛人发送页、选择设备、确认发送，也无需接收端预先按键准备。手动发送只是未标记内容的可选入口。应用排除名单负责不记录；自动发送依靠敏感标记，两者不能混为同一项判断。Windows 默认排除列表包含 1Password；Android 不声称已经有按来源程序名过滤的同等能力。

发送端允许读取系统剪贴板，不能保证其他有权限的软件未读到；敏感内容跳过猛人的普通历史与普通同步。接收端不写系统剪贴板，不入历史或 Replica，不再转发。单条最多 16 KiB，拒绝控制字符；各端单次消费、最多两分钟，锁屏/禁收/退出/解绑清除，无离线秘密队列。

## 接收与输入

Android 在键盘上方只显示“私密内容已到 · 点此直接填入”。点击时才经 JNI 取出文字，调用当前 InputConnection，不经过学习引擎。无内容时仅提示尚无待用内容，不开始等待，不改变以后输入的授权。

Windows 默认 Ctrl+Alt+V：有待用内容就直接输入，否则保留打开历史的既有行为。独立私密快捷键和托盘“填入已收到的私密内容”只消费当前内容，无内容时不会开启等待。手动与可选自动输入共享单任务许可；任务开始即取出本次内容，失败不能清掉任务期间新到的另一条。修饰键释放、窗口与锁定状态复核后才用 Unicode SendInput，不回退系统粘贴。符号快捷键仍支持 Ctrl+Shift+?。

两端“密码框自动填入”保留为可选设置，新配置默认关闭；已有用户明确保存的开关继续生效。开启后仅在接收时存在活动密码框时尝试，不在稍后打开的任意密码框补填。此功能依赖系统控件标记，不验证账号或网站归属，也不是完整的 Android Autofill provider。

## 自动捕获与生命周期

Android 复制监听由应用进程持有，启动同步及监听不要求键盘窗口展开，IME 销毁只解绑 UI 回调，不再清除进程级接收槽。系统结束整个进程后无法继续后台接收，不承诺常驻。受系统限制读不到剪贴板或进程未运行时，不能声称复制必达。

敏感复制使用独立的无正文时间戳去重，只有 JNI 成功受理后台任务才持久化；未受理不标成功。重新捕获只尝试两分钟内的新复制，避免进程恢复后发送陈旧密码。已受理但网络失败不自动补发，用户重新复制即可开启新投递。

## 投递确认与提示

每轮发出 started 元数据并清理上轮显示；按每个直接配对目标报告“确认接收/未获确认”，最终只报告确认台数。最多四个并发目标，不再因全局十五秒截止而直接跳过后续目标。对端 ACK 表示入临时槽，收尾帧失败不撤回已经收到的 ACK；缺少 ACK 仍只能表示未确认，不能断言对端没有收到。

Android 同步页、Windows 设备页按设备展示本轮结果。日志仅包含阶段、脱敏设备编号和确认布尔值，没有密码、摘要、长度或预览。接收确认不等于已填入；目前没有把输入成功回传发送端的协议。

输入操作不再产生准备/取消/等待过期通知。Android 只保留一个当前 Toast、重复提示去重；Windows 提示限频并使用实时投递标志，避免系统积压过时气泡。新建服务后旧 Android poller 回调被丢弃。

## 1Password 对接的取舍

查阅[分享说明](https://support.1password.com/share-items/)、[导出说明](https://support.1password.com/export/)和[桌面 SDK 授权](https://www.1password.dev/sdks/concepts)：未确认“在 1Password 当前条目直接交给猛人单次发送”的公开接口。Credential Exchange 面向迁移、从接收端发起导入；桌面 SDK 授权范围较大。用户已决定不把两端都绕过剪贴板作为本轮要求，保留上述复制后自动发送流程。

## 验证边界

自动验证应覆盖并发重复输入、任务失败后新槽不被误清、未受理可再次捕获、已受理不重放、过期复制不自动发送、三台逻辑设备六方向收发、逐目标确认、锁屏/禁收/解绑及无正文文件。Android Kotlin 编译与 Rust Windows/JNI 编译分别验证。

已有魅族到华为/台式机的用户确认，其余路线仍需[真机定向检查](../user/help/mengren-testing.md)：魅族从 1Password 复制一次，在未打开键盘的情况下由华为和电脑分别接收，稍后主动填入；同时观察历史与系统剪贴板。保留每条路线的独立结果，不据此宣称所有设备、后台状态和目标应用都已解决。

## 0.4.2 魅族提示交互修复

用户确认电脑到安卓传输可用，但魅族提示期间不能取消或点候选。提示现在仅在候选为空时占中间区域，固定入口与收起、丢弃可用；候选触摸不再被私密提示的遮挡条件整体屏蔽。只在明确的私密输入动作上检查本次完整手势遮挡，多指或取消会撤销该手势授权。丢弃调用现有 Native clear，不切换接收权限，不转写普通历史。有效期仍为两分钟，与界面可操作性无关。新版本魅族实际使用待用户确认。

# 私密互传与自动填充

## 调研结论

2026-11-06 根据用户提出的手机间操作问题核对以下一手资料：

| 方案 | 适合什么 | 对本项目的决定 |
| --- | --- | --- |
| [1Password 自动填充](https://support.1password.com/android-autofill/) | 已保存在密码管理器里的账号；按应用或网站匹配登录项 | 保留原服务，用户已有密码库时优先使用；输入法不另建密码库 |
| [Android 键盘内联填充建议](https://developer.android.com/identity/autofill/ime-autofill) | 在目标输入框附近展示可选择的填充项 | 参考交互：只显示“私密内容已到”，点击时才经 JNI 取出明文。本版不是完整系统 Autofill provider 或其内联建议接入 |
| [KeePassDX Magikeyboard](https://github.com/Kunzisoft/KeePassDX/wiki/Magikeyboard) | 键盘直接输入，不通过系统剪贴板，减少表单识别依赖 | 采用同类直接输入方式，适合本项目临时跨设备内容；参考设计，未复制其源代码 |
| [Bitwarden Send](https://bitwarden.com/help/send-encryption/) 与 [1Password 分享链接](https://support.1password.com/share-items-security/) | 向其他人提供限时分享链接 | 这些方案在服务器保存加密副本，接收端还需打开链接；不作为频繁自用互传的默认流程 |

这些资料支持不同产品的交互与安全模型，不代表本软件获得了相同审计或同等的账号/域名匹配能力。

## 产品范围

v0.3.7 的 Android 和 Windows 均可发送、接收。只向已配对、在线且允许接收的设备发送，接收端锁定或灭屏时拒收。服务端仍只转发密文，已有 v0.3.6 中转兼容，不新增域名、端口或持久化消息。

两个平台均默认开启密码框自动填入；可以单独关闭。只有接收时已有明确的活动密码输入框才自动填入。无法识别的控件和普通输入框不自动猜测用途；用户可以点击提示、使用私密输入快捷键，或事先为具体输入框准备一次等待。

这是临时文字输入，不是密码管理器的域名匹配：软件只知道目标控件的密码标记，不知道这段密码属于哪个账号。单条 16 KiB，最多两分钟、各接收端单次使用；不入普通剪贴板、不入 Replica，不离线补发。

## 手机接收

`PrivateReceive` 注册灭屏、亮屏、解锁广播；当前屏幕交互状态与 Keyguard 状态共同决定 Rust 的接收可用性。广播注册失败时不开放接收，关闭同步会撤销权限并注销广播。

收到事件只包含类型，不包含正文；`clipboardSyncPrivatePending` 只查询是否存在有效槽。键盘空闲区域显示“点此直接填入”，不显示密码、长度或预览；真实输入通过专用 JNI 取出一次并调用当前 `InputConnection.commitText`，不经过学习引擎。正在组拼音或打开编辑条时不会自动提交。

光标位于 Android 标记的密码框、键盘已显示且开关开启时，收到事件直接填入。收到时没有活动目标则保留提示，稍后打开其他输入框不会无确认地补填。

解锁图标在无内容时准备一次等待；`PrivateTarget` 以弱引用绑定实际 InputConnection 和单调时钟，到期、切换输入框、收起键盘、锁屏或关闭接收时取消。再次点击取消等待。提示只用于当前输入框，不是系统悬浮窗。

## 电脑接收

Windows 自动填充在后台 MTA 线程使用 UI Automation，只查询焦点对象、控件类型、可用性和 IsPassword，不读取 Value 或输入内容。普通自动模式要求活动控件标为密码框；等待模式绑定具体 UIA 元素，在前台窗口或元素改变时取消。取用前复核焦点、锁定状态和修饰键，最后使用 SendInput Unicode。识别为密码框时先选择该框内容，避免追加到旧密码后。

同一时刻最多一个自动填充任务；用户指定的等待任务也只有一个。窗口或焦点不符时保留未消费槽供用户明确输入，已经消费而输入失败的内容不恢复到剪贴板。

默认 Ctrl+Alt+V 保持与历史面板共用；专用快捷键改成独立组合后，无内容时可为当前框准备等待。托盘也提供等待入口。密码框自动填入不要求先按快捷键。

## 发送与权限边界

Windows 私密发送直接由监听线程调用弱服务句柄，不把正文塞进面板事件队列。已标敏感的复制可自动发出，暂停记录会暂停自动发送；托盘与独立快捷键支持手动。默认 Ctrl+Alt+Shift+V，发送、接收快捷键均可独立录制。

符号解析支持可打印 ASCII，包括 `?`、`/`、`;`、`+`。设置录制、占用检查和实际 RegisterHotKey 共用当前布局的键映射；Shift+/ 录制为 ?，冲突按物理键和有效修饰键判断，避免 `Ctrl+Shift+/` 与 `Ctrl+Shift+?` 重复注册。加号配置用末尾 `++` 无歧义表示。

Shared 的接收权限和屏幕可用性在短临界区内更新；提交槽时重新检查配对和权限，并在网络确认前释放锁，避免用户关闭接收时被网络阻塞。锁屏保险箱撤销、配置禁用、解绑和退出均清理内存。配对后在线列表可能尚未推送，私密发送让中转按当时实际注册状态接通，不为此建立离线队列。

## 验证边界

自动测试覆盖三台逻辑设备的六个方向、单次消费、禁收、灭屏状态、无普通副本和无正文文件；手机输入目标测试覆盖身份、过期、取消和重新授权；符号录制测试覆盖问号和斜杠物理冲突。

这些测试不能替代各手机 ROM、浏览器、银行应用或管理员窗口的实际验收。用户已确认 v0.3.6 手机到电脑可用，v0.3.7 新增的自动填充交互仍需要真实应用验证。自定义控件可能不提供密码标记；此时使用明确的等待或手动输入，不改用系统剪贴板兜底。

# 语音与滑行输入

手机特有的两种输入方式（2026-10-20）。框架先搭好：入口、界面、设置项和跨平台接口都已定下，识别与解码的实现往里填，只换实现，不动入口与界面。语音已接上火山引擎的云端识别，滑行按词表给轨迹打分解码。
Android 上怎么接的见 [notes/android.md](../notes/android.md)「语音输入」。

## 分工

按 [contributing.md](../contributing.md) 的约束：以后各平台都能用的部分放 Rust，平台壳只做平台相关的事。

| | Rust（各平台共用） | 平台壳 |
|---|---|---|
| 语音 | 识别结果上屏 `Engine::commit_voice`；云端与本地离线识别实现 `qingjian_core::Transcriber`（云端在 `qingjian-voice`） | 录音、系统自带的识别器、麦克风权限、语音面板、识别服务的设置页与密钥保管 |
| 滑行 | 解码 `qingjian_core::SwipeDecoder`（轨迹 + 键位几何 → 字母串），解出的字母经 Session 像点按一样进组句 | 判定点按还是滑行、记轨迹、画轨迹、交键位几何 |

## 语音

### 识别结果怎么回到输入框

不论哪种识别方式，最终结果都经 `Engine::commit_voice` 上屏：繁体输出开着时转繁体，记进输入历史（云联想的上文）、例句、输入日志（来源 `voice`）和输入统计。
统计里语音按字数与切出来的词数算，不算选词，也不计键数与时长，所以首选率、码长这些打字指标不受影响。不记词频：识别结果不是从候选里挑的。

说话途中的中间结果只是显示，不进 Core：壳把它作为编辑中的文字放进输入框，最终结果上屏时替换掉；取消就撤掉。

### 识别方式

能装下四类识别方式，入口与界面不用改：

- **系统识别器**（Android `SpeechRecognizer`、iOS `SFSpeechRecognizer`）：平台 API，实现留在壳里。
- **调系统语音输入法**：把输入法临时切过去，结果由那个输入法直接写进输入框，壳里实现，不经 Core。
- **云端识别**、**本地离线模型**：各平台都能用，实现 Core 的 `Transcriber`，放独立 crate（与云联想一样，Core 本身不联网）。

`Transcriber` 是非阻塞接口：`start(采样率)` → 若干次 `feed(单声道 16 位 PCM)` → `finish()` 或 `cancel()`，结果由壳定时 `poll()` 取，事件是中间结果、最终结果、出错三种。
`available()` 为假时入口只提示「还不能用」。

### 云端识别：火山引擎豆包流式语音识别

现在接的第一个识别服务（2026-10-20），在 `crates/qingjian-voice`：豆包流式语音识别模型 2.0，走大模型流式识别的 WebSocket 接口（`bigmodel_async`，结果有变化才回包）。

- 一段识别一条连接，开在后台线程上：连上时带 `X-Api-Key`（新版控制台的 API Key）与 `X-Api-Resource-Id`（小时版 `volc.seedasr.sauc.duration` 或并发版 `.concurrent`），先发识别参数（PCM 16 kHz 单声道、标点、数字规整、二遍识别），再每 200 ms 发一包音频，说完发负序号的最后一包，等带「最后一包」标志的回包当最终结果，8 秒没等到算超时。
- 帧是 v3 二进制协议（4 字节头 + 序号 + 长度 + gzip 载荷），回包里取 `result.text`（整段，不是增量）当中间结果。
- 加密连接用 rustls（ring + 内置根证书），桌面与安卓同一套，不依赖平台证书库。
- 配置（服务、密钥、计费方式）是平台设置里单独一页，与云联想、翻译用的大模型配置分开：两者是不同的服务、不同的密钥，用户可能只开一样。
- 出错（密钥无效、没网、服务繁忙、超时）交回一句给用户看的话，入口照常收起面板。

### 本机离线识别：sherpa-onnx + SenseVoice

2026-11-09 加入（安卓），在 `crates/qingjian-voice-offline`，与豆包并列为「识别服务」的一个选项，用户自己选：离线不联网、不花钱、录音不出设备，云端在嘈杂环境和长句上更稳。
方案与猛人快传一致，模型也是同一份。

- 引擎：sherpa-onnx（k2-fsa，Apache-2.0）的 C 接口，运行时加载（dlopen / LoadLibrary），不在链接期依赖：库缺失或版本不对时输入法照常运行，只是离线识别不可用。
  调用前核对库报的版本（`EXPECTED_VERSION`），因为识别配置是按整个 C 结构体传的，版本不对结构体会错位。安卓的两个库（`libsherpa-onnx-c-api.so`、`libonnxruntime.so`，16 KB 页对齐）由 Gradle 从 pub.dev 的 `sherpa_onnx_android_arm64` 包取，核对 SHA-256。
- 模型：SenseVoice Small int8（FunAudioLLM，FunASR 模型许可），用 k2-fsa 转换的 **2024-07-17 官方原版**；2025-09-09 那版是粤语专用模型转来的，普通话漏字多，不用。
  约 229 MB，不随安装包，首次使用前从猛人快传 GitHub 预发布页 `asr-model-sensevoice-2024-07-17` 下载，走与检查更新相同的代理；断点续传、30 秒无数据算卡住、下完核对大小与 SHA-256 才写校验标记。
- 识别：SenseVoice 不是流式模型，说话途中每约 0.9 秒把当前段整段重识别一次当中间结果，说完识别最后一遍；当前段超过 20 秒时在第 10～20 秒里最安静的 0.1 秒处切开，前一段先识别成文字存着，避免长段又慢又掉字。打开逆文本规整（数字写阿拉伯数字、带标点）。
  电脑上实测：6 秒中文说完后 0.13 秒出最终结果，34 秒长段 0.27 秒；手机上要慢几倍。
- 内存：模型在进程里只加载一份（第一次说话时加载，约一两秒），空闲 3 分钟由后台线程释放；换识别方式不重新加载。
- 清理：模型放 App 私有目录 `files/voice-model/<版本文件夹>/`；App 启动时删掉别的版本文件夹和超过 7 天没续上的半截下载；设置页显示占用并能一键删除（删除前先放掉内存里那份）。
  Gradle 下载的引擎包缓存在 `data/third_party/sherpa-onnx/`，只留当前版本。

桌面验证：`cargo run -p qingjian-voice-offline --example transcribe -- <模型根目录> <引擎库目录> <WAV>`，先整段识别，再模拟边说边喂打印中间结果。

### 交互

- 入口：按住空格不动约 400 ms（键盘设置「长按空格说话」，缺省开）、工具栏的话筒、全面屏底栏的语音键，三处进同一个入口。
  按住空格后横向滑动超过一格是移动光标，与语音不冲突；语音开不起来（还不能用、没有权限）时按住空格照旧移动光标。
- 面板盖住候选条与键盘：底板上一团主题色的光，上方一条随音量起伏的细波形，中间一段弧分两块，左「撤回输入」、右边照搬输入框回车动作的文字（发送、搜索…，多行框没有动作，写「完成」），下面一行提示、一个圆钮，最底一排 ⌄ 与键盘图标。
- 按住空格说话：手指滑到哪块上松手就是哪个——「撤回输入」撤掉编辑中的字，右块上屏后执行回车动作（聊天框里即发出），别处松手只是说完、上屏。
- 点按进来：两块弧都能点；圆钮（画话筒）与键盘图标是说完、回到键盘；⌄ 是说完、上屏后收起键盘。
- 要录音的识别方式先查麦克风权限，没有就开一个透明窗口弹系统权限框（输入法服务弹不了），给了直接开始。

## 滑行

### 范围

只给拼音全键盘与英文键盘（26 键），设置「滑行输入」缺省关。九宫格、注音不是字母键；双拼、五笔的字母不是这样拼词的，日语暂不给。

### 解码接口

壳交两样东西：轨迹（一串点）与各字母键的中心和大小，坐标是壳那边的像素，同一个坐标系即可。键位每次随轨迹一起交，不在 Rust 里另存一份键盘布局：键盘高度、全面屏、横竖屏一变键位就变，跟着交最省事，将来键盘统一到 Rust（Phase 5）时再改成直接读。

`SwipeDecoder::decode(轨迹, 键位, 候选词)` 按可能性从高到低回几个小写字母串，现在只用第一个。解出的字母像一个个点出来的一样进组句（拼音照常切音节、出候选，英文照常出英文词），所以候选、选词、学习、统计都不用为滑行另做；英文键盘不组句时字母串直接上屏。

候选词（`SwipeLexicon`：字母串加 log10 词频的先验）由调用方按当前在打什么给，解码本身不知道中英文：

| 在打什么 | 候选词 |
|---|---|
| 中文（拼音全键盘） | 主词库每个词的音节连起来（`zhongguo`），同一串的各词词频相加；单音节也在里面 |
| 英文模式、字母直接上屏 | 随包英文词表，词频是 Zipf × 1000 |
| 日语（现在键盘上不开滑行） | 空：没有词可比，退回按拐点取字母的 `CornerDecoder` |

两份词表在第一次滑行时才建（各几十毫秒），之后常驻；用户自己打过的词、附加词库不收，新词点按打。

`ShapeDecoder` 的打分（实现见 `swipe/shape.rs` 文件头）：每个候选词依次连起各字母键中心是它的「理想路径」，坐标按键宽高归一，形状差是几项距离平方之和——两条线按长度重采样成 48 个点逐点比的均方、词的字母按顺序在轨迹上找最近点的均方（直线顺路划过的字母也算经过）、轨迹离理想路径最远的一点（轨迹拐去的地方词里得有字母，`nihao` 不解成 `niao`）、起点与终点各自离首尾字母的距离（`hello` 与 `help` 只差终点一个键）。总分是 `先验 − 5 × 形状差`。

- 只比首尾字母键在起点、终点 1.1 个键宽内的词（按首尾字母分桶），路径长度与轨迹差太多（超过 1.8 倍再加一个键宽）的跳过。
- 起终点的差只取决于首尾字母，`先验 − 5 × 起终点差` 是总分上限：按上限从高到低比，上限不如第五名、或比第一名低 6 分以上就停；一个词的几项按便宜到贵算，超了预算就停。随包词表上电脑一次不到 1 ms，最长的词几毫秒。
- 同一个键连着两次（`ll`）在路径上是同一个点，靠词频分：`hello` 比 `helo` 常用；`to` 与 `too` 形状一样，取更常用的 `to`。
- 用带噪声、抄近路的模拟轨迹在随包词表上评过：英文 54 个常用词、拼音 50 个常用音节串与词，首选对的英文约 98%（错的是 `too`、`there`）、拼音约 99.6%，正确的词都在前五。

以后可以加上前文的语言模型（整句接着前一个词打分）与用户词，接口不变。

### 交互

- 手指落在字母键上就开始记点，离起点挪开 0.6 个键宽才算滑行；之前照常是点按（按下态、气泡、长按选符号都在）。转成滑行时撤掉按下态与长按。
- 滑行时画一道主题色的线，抬手交给解码、线消失。
- 第二根手指在滑开之前落下，说明是在快打，这一笔不当滑行；滑开之后落下的手指不理。

## Windows 麦克风与光标上屏

Windows 用右 Alt 长按作为默认语音入口。设置还提供右 Ctrl、任一 Win、自定义组合键和关闭快捷键。旧配置已经指定组合键时沿用原键。短按修饰键或用它组成普通快捷键时照常放行，达到阈值后才发送一次遮罩键，物理抬键始终交回系统。录音时按 Esc 丢弃当前段。「说」按钮另支持点击开始、再点结束。按住期间又按下别的修饰键、点鼠标或滚滚轮，这次按住作废。自定义组合键含 Win 或 Alt 时，吞掉主键后同样补发遮罩键。低级键盘 / 鼠标钩子装在专用的高优先级线程上：钩子回调超过 LowLevelHooksTimeout 会被系统静默卸载，不能与要画候选窗的 UI 线程共用。

翻译窗口快捷键（组合键或双击右 Ctrl）：Server 先看前台焦点会话的 DLL 是否在 `SyncMode` 里声明 `reads_selection`；是且不是私密输入，就在下一次 `ModeSync` 带 `read_selection` 请求号，DLL 用只读编辑会话读选区（翻译窗口用途最多 4000 字、超出截断，不进原地评审），以 `Selection` 回；Server 收到后经管道（`--stdin`，不放命令行）交给 `qingjian-translator`，窗口已开时新实例用 `WM_COPYDATA` 转交。DLL 要不到编辑会话（网页正文这类非可编辑内容会被拒）时立即回 `Selection.unreadable = true`。输入法读不到（unreadable、0.7 秒内没回、旧 DLL、不是猛人会话）时，Server 在后台线程依次试系统辅助接口（UI Automation TextPattern，限时 0.8 秒；Win32 原生 EDIT 不提供 TextPattern，靠前一步 TSF 覆盖）和模拟 Ctrl+Insert（不用 Ctrl+C：终端里是中断）：先等修饰键松开，存下剪贴板原内容（太大或 0.3 秒内打不开就整步跳过），复制后读文字，再限时 3 秒放回原内容，只标 `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 为 0。**不能**标 `ExcludeClipboardContentFromMonitorProcessing`：猛人剪贴板把它当密码管理器的密码，会私密发给已配对设备。输入框读到了但没选中时只试辅助接口不复制（有的编辑器没选中时复制整行）；私密输入什么都不读；翻译窗口自己在前台时只收起。

原地翻译（双击右 Shift，`dispatch/translate/in_place/`）：前台是能读选区的猛人会话时，下一次 `ModeSync` 带 `read_selection` 加 `review_selection`，DLL 按「翻译选中文字」读，读到就走原有评审并记下选区范围（接受时直接 `SetText` 替换它，不信回车时的当前选区——ChatGPT 桌面版会把选区收成光标）；读到空选区（微信、WPS、原生 EDIT 这类经兼容层的程序总报空）、读不了或超时，就调注入的 `SelectionProbe`（辅助接口加模拟 Ctrl+Insert）取文字，取到后发翻译、画「翻译中…」，下一次 `ModeSync.start_review` 让 DLL 进评审态（2 秒没接上就收起）。Ctrl+Alt+T 读到空选区时同样走这条兜底。私密输入不兜底；前台不是猛人会话或取的时候换了窗口，改开翻译窗口。注意 `ensure_focus` 换焦点时会清在等的读选区请求，认领选区后要记回去。

交给 DLL 的读选区请求与 `start_review` 只放进声明了 `reads_selection` 的那次同步（空闲轮询）；DLL 获焦时补的同步不处理这两项，交给它就丢了。`start_review` 一直带到 DLL 来轮询（确认收到）或 2 秒超时。DLL 在 `SyncMode.in_place_review` 声明自己认得原地评审，0.4.14 之前的 DLL 不声明，Server 改开翻译窗口显示译文。能力记录只记不清，会话关闭才忘。DLL 判断「前台」时键盘焦点在本线程也算（WPS 外框与编辑区分属两个进程）。DLL 吃掉带 Alt / Win 的保留键后补发遮罩键 0xE8：否则应用把单独松开的 Alt 当成进菜单访问键模式，短暂夺焦让刚开始的评审被落定结束（记事本、WPS 实测）。兜底取文字时 Ctrl+Insert 没复制到再试 Ctrl+C（Flutter 不认 Ctrl+Insert），前台是终端或带终端的编辑器（按进程名、窗口类）时不发 Ctrl+C。两个协议字段都带 `serde(default)`，新旧端互读不出错，不升 `PROTOCOL_VERSION`。双击判定：右 Ctrl 单独按下且 0.3 秒内松开算一次轻点，上次松开到这次按下不超过 0.4 秒算双击；中间有其他按键、修饰键、鼠标或触发了语音都作废；右 Ctrl 本身不拦。

Server 把识别终稿留在发起会话的待上屏队列。处于前台的 DLL 在空闲模式轮询中先取得当前 TSF 焦点文档，然后声明可以接收文字。Server 原子取走队列，DLL 在异步编辑会话中写入当前光标。协议沿用原版本号，两字段均有反序列化默认值。旧 DLL 在按键或 Poll 时取回终稿，重开宿主应用加载新 DLL 后即可空闲上屏。

### Windows 听写目标

全局快捷键和悬浮条开始录音时读取 Windows 前台输入队列的焦点窗口及线程。语音结果单独进入对应会话的待交付队列，有效期五秒。窗口或线程改变时取消录音或丢弃待交付结果。空闲的 TSF 线程只在自己拥有焦点时声明可接收上屏文字，异步编辑执行前再核对焦点窗口和文档上下文。
